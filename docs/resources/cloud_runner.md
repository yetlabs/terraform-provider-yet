# Resource: yet_cloud_runner

GitHub Actions runners kept by a runtime: a native one — a Mac or Windows, whose agent runs as its own `yetd` account — for the builds only that system makes; or a k3s one, on Linux or in Windows's WSL, each copy a pod sandboxed by gVisor, with a Docker of its own for `docker run`, `build` and `compose`, nothing privileged on the machine. Each copy takes one job and starts again clean. Cloud asks GitHub for their registration tokens, a new one before each expires; the machine never holds the company's token.

-> **Note:** Cloud asks GitHub with the runner's own `github_token`, or, without one, with the company's GitHub connection — `yet_settings_connection_github`. Either must be able to manage the repository's or the organization's runners: a fine-grained token with *Administration: read and write* on the repository, or *Self-hosted runners* on the organization.

~> **Note:** Only Cloud admins define runners: a job runs on the company's machine, so they are for the company's own repositories.

## Example Usage

```terraform
resource "yet_cloud_runtime" "mac" {
  name      = "mac-mini"
  stack     = "local:native"
  server_id = yet_cloud_server.mac.id
}

# The organization's macOS runners, registered with the company's GitHub connection.
resource "yet_cloud_runner" "ios" {
  runtime_id = yet_cloud_runtime.mac.id
  name       = "ios"
  url        = "https://github.com/acme"
  labels     = ["macos", "xcode-16"]
  replicas   = 2

  depends_on = [yet_settings_connection_github.acme]
}

# Linux runners on a k3s runtime: each copy sandboxed by gVisor, with a Docker
# of its own for docker run, build and compose — one always ready, up to four
# while jobs wait (the company's GitHub connected as Cloud's App).
resource "yet_cloud_runtime" "builder" {
  name            = "builder"
  stack           = "local:traefik+k3s"
  server_id       = yet_cloud_server.builder.id
  ingress_enabled = false # runners only
}

resource "yet_cloud_runner" "ci" {
  runtime_id   = yet_cloud_runtime.builder.id
  name         = "ci"
  url          = "https://github.com/acme/shop"
  labels       = ["linux-docker"]
  replicas     = 1
  max_replicas = 4

  depends_on = [yet_settings_connection_github.acme]
}
```

## Schema

### Required

- `name` (String) Its name on the runtime: lowercase letters, digits and dashes, up to 32.
- `runtime_id` (String) The runtime they run on: a native one (`local:native`, a Mac or Windows), or a k3s one (`local:traefik+k3s`), on Linux or Windows.
- `url` (String) What it runs for, on GitHub: an organization, `https://github.com/acme`, or a repository, `https://github.com/acme/ios`.

### Optional

- `enabled` (Boolean) Whether it runs. `true` unless set.
- `github_token` (String, Sensitive) A GitHub token of its own; the company's GitHub connection is used without one. Sealed in Cloud, never shown again — taken away from the config, the one given stays.
- `labels` (Set of String) Its labels, for workflows' `runs-on`: letters, digits, dots, dashes and underscores.
- `max_replicas` (Number) On a k3s runtime, up to how many copies it grows, one a job GitHub queues for it — from `replicas` up to this, back down as the jobs complete; a copy busy with a job is never stopped. `0`, unless set, keeps it at `replicas`.

  Cloud hears of the jobs through its GitHub App's `workflow_job` events: the company's GitHub must be connected as the App (`yet_settings_connection_github`), not with a token.
- `replicas` (Number) How many copies run, each taking a job: 1 to 20, `1` unless set. Growing (`max_replicas`), the fewest always there — `0` too.

### Read-Only

- `has_token` (Boolean) Whether it has a GitHub token of its own.
- `id` (String) The ID of this resource.
- `problem` (String) What GitHub said, when it would not register it.
