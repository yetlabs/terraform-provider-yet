# Resource: yet_settings_person

Someone of the company with a mailbox here, who signs in with it.

!> **Warning:** Destroying it removes their sign-in and their mailbox, with every message in it. It cannot be undone.

-> **Note:** An invitation waits for a person to open it, so it stays in Yet's apps: here, people are given a password.

## Example Usage

```terraform
resource "yet_settings_person" "ana" {
  name      = "ana"
  domain    = "acme.dev"
  aliases   = ["acme.com.br"]
  full_name = "Ana Costa"
  password  = var.ana_password
}

variable "ana_password" {
  type      = string
  sensitive = true
}
```

## Schema

### Required

- `domain` (String) One of the company's domains with mail: their address is `name@domain`.
- `full_name` (String) Their name, as the apps and their mail show it.
- `name` (String) Their mailbox's name, before the @: `ana`.
- `password` (String, Sensitive) Their password when they are added, at least 8 characters. Setting it again takes a person signed in to Settings — an API key never sets someone else's — so changing it here is refused; imported, it is taken as given.

### Optional

- `admin` (Boolean) Whether they may open the company's Settings. Only a person signed in to Settings gives it — `true` with an API key is refused — so here it is read, or set to `false` to take it away; left out, it stays as Settings has it.
- `aliases` (List of String) Other domains of the company with mail where `name@` reaches them too.

### Read-Only

- `email` (String) The address they sign in with.
- `id` (String) The ID of this resource.

## Import

In Terraform v1.5.0 and later, with an [`import` block](https://developer.hashicorp.com/terraform/language/import):

```terraform
import {
  to = yet_settings_person.ana

}
```

With [`terraform import`](https://developer.hashicorp.com/terraform/cli/commands/import):

```shell
# By the person's id, as Settings → People has it. The password given is
# taken as theirs: Terraform never sets it again.
terraform import yet_settings_person.ana 3c
```
