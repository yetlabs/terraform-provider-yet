# Resource: yet_cloud_application_addon

An application's own database — Overlite, Postgres or Redis — its add-on: run beside it on each of its stages, each stage's its own, and handed to it in a variable. Or an S3 bucket, `s3`: one on each stage, in that stage's AWS account, reached as the stage's one identity there — by its EC2 servers' role, or with a key — each bucket a policy on it.

-> **Note:** For one database that several applications share, make it an environment's — `yet_cloud_database` — and attach it with `yet_cloud_database_attachment`.

~> **Note:** Destroyed, it stops at the agents' next look — its volume stays on each server. Back it up first with the `yet_cloud_database_backup` action. An S3 bucket stays in its account: only the application's way to it is taken away.

## Example Usage

```terraform
# A Postgres of the API's own, on each of its stages.
resource "yet_cloud_application_addon" "db" {
  application_id = yet_cloud_application.api.id
  kind           = "postgres"
  features       = ["pgvector"]
  memory_mb      = 1024
}

# A cache beside each copy of it, on every member of a pool.
resource "yet_cloud_application_addon" "cache" {
  application_id = yet_cloud_application.api.id
  kind           = "redis"
  env_var        = "CACHE_URL"
  placement      = "member"
  features       = ["volatile"]
}

# A bucket on each of its stages, in each stage's AWS account: S3_BUCKET,
# S3_REGION and S3_ENDPOINT, and the way in, handed to it.
resource "yet_cloud_application_addon" "files" {
  application_id = yet_cloud_application.api.id
  kind           = "s3"
}

# Its buckets chosen: staging's a new one, named; production's, one its
# account has already — reached, never made.
resource "yet_cloud_application_addon" "media" {
  application_id = yet_cloud_application.api.id
  kind           = "s3"
  env_var        = "MEDIA"
  bucket = [
    { environment_id = yet_cloud_environment.staging.id, name = "yet-acme-api-media-staging" },
    { environment_id = yet_cloud_environment.production.id, name = "acme-media", existing = true },
  ]
}
```

## Schema

### Required

- `application_id` (String) The application it is of.
- `kind` (String) `overlite`, `postgres`, `redis`, `s3` or `bucketdb` — a Postgres in a bucket of each stage's, served beside each copy of the application, one to an application.

### Optional

- `bucket` (Attributes List) An `s3` add-on's buckets, chosen stage by stage: a new one's `name` — it begins `yet-<company>-` — or, `existing`, one the stage's account has, reached and never made. A stage not given one gets a bucket Yet names. (see [below for nested schema](#nestedatt--bucket))
- `env_var` (String) The variable the application is handed its address in — capitals, digits and underscores: `DATABASE_URL` for Overlite, Postgres and BucketDB, `REDIS_URL` for Redis, unless set. For `s3`, the prefix of what it is handed — `S3_BUCKET`, `S3_REGION`, `S3_ENDPOINT` — `S3` unless set.
- `features` (Set of String) What it runs with: `pgvector` for Postgres; `volatile`, `evict` for Redis.
- `memory_mb` (Number) The memory it may use, in MB: 128 to 65536, or `0` for no limit.
- `placement` (String) On a pool: `shared` — one, on its first member — or `member`, one on each. Overlite and Postgres are shared, Redis each member's, unless set.
- `stopped` (Boolean) Whether it is stopped: kept, not running.
- `studio_read_only` (Boolean) Whether the studio only reads.
- `studio_role` (String) Who opens it in Cloud's studio: `viewer`, `developer` or `admin`.
- `version` (String) The version it runs; the newest unless set.

### Read-Only

- `buckets` (Attributes List) An `s3` add-on's buckets, one on each stage. (see [below for nested schema](#nestedatt--buckets))
- `id` (String) The ID of this resource.
- `image` (String) The image it runs.
