# Resource: yet_vault_vault

A vault: a set of the company's secrets, a folder of Vault's bucket in its own AWS account — the bucket the stack of the account connected for Vault makes, private, encrypted with the account's key, each value's versions kept — never in Yet, which knows their names alone. Destroyed, an empty vault is forgotten; the bucket keeps what was in it.

-> **Note:** An AWS account connected for Vault first (`yet_settings_aws_account` with `vault` in its `uses`), its stack from template 9 on.

## Example Usage

```terraform
# Vault's one bucket is made by the stack of the account connected for it.
resource "yet_settings_aws_account" "secrets" {
  name   = "Secrets"
  region = "sa-east-1"
  uses   = ["vault"]
}

# What the company's applications read: production's, for systems.
resource "yet_vault_vault" "production" {
  name        = "Production"
  description = "What our applications sign in with."
}

# The engineers', shared: who reads it is given in Yet's apps.
resource "yet_vault_vault" "engineering" {
  name = "Engineering"
  kind = "shared"
}
```

## Schema

### Required

- `name` (String) Its name, the company's only one so named.

### Optional

- `description` (String) What it is for.
- `kind` (String) Who reads it: `systems` (the default), the applications it lets (`yet_vault_grant`); or `shared`, people of the company, given it in Yet's apps — a person signed in, never a key. A person's own vault is theirs to make there.

### Read-Only

- `aws_account_id` (String) The AWS account its secrets are in: the one connected for Vault.
- `bucket` (String) Vault's bucket, in the account: its secrets are under `vaults/<kind>/<id>/`, by id, never by name.
- `id` (String) The ID of this resource.
- `region` (String) Vault's bucket's region.
