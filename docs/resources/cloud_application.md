# Resource: yet_cloud_application

Something the company runs, through its stages — one environment each, in order: staging, then production. Built from a GitHub repository, or released from an image.

## Example Usage

```terraform
resource "yet_cloud_application" "api" {
  namespace_id = yet_cloud_namespace.shop.id
  name         = "api"
  stages       = [yet_cloud_environment.staging.id, yet_cloud_environment.production.id]
  auto_promote = [yet_cloud_environment.staging.id]

  repository = "acme/api"
  branch     = "main"
  replicas   = 2

  # Destroyed, its add-ons go with it — kept, unless said.
  addons_on_delete = "delete"

  # The site at each stage's address; its admin at its own, back-office
  # before it; its metrics inside the cluster only.
  ports = [
    { name = "http", port = 3000, public = true },
    { name = "admin", port = 9000, public = true, address = "back-office" },
    { name = "metrics", port = 9100 },
  ]

  # A copy takes requests once /healthz answers, and is restarted when it
  # stops answering on its admin port.
  readiness = {
    port = "http"
    path = "/healthz"
  }
  liveness = {
    port              = "admin"
    protocol          = "tcp"
    period_seconds    = 20
    failure_threshold = 5
  }

  # Each copy up to half a core and 512 MB.
  cpu_millicores = 500
  memory_mb      = 512

  # Up to six, scaling out past 60% of the processors or 80% of the memory.
  max_replicas = 6
  scale_cpu    = 60
  scale_memory = 80

  env = {
    LOG_LEVEL = "info"
  }
  stage_env = {
    (yet_cloud_environment.production.id) = {
      LOG_LEVEL = "warn"
    }
  }

  # Staging on one copy of 256 MB, never growing; production keeps the
  # size above.
  environment_size = {
    (yet_cloud_environment.staging.id) = {
      replicas     = 1
      max_replicas = 1
      memory_mb    = 256
    }
  }
}

# Two applications of a monorepo, in one namespace: the panel built from its
# own Dockerfile — from the repository's root, so it reaches the schema
# beside its folder — and handed the worker's address inside the cluster.
resource "yet_cloud_application" "worker" {
  namespace_id = yet_cloud_namespace.shop.id
  name         = "worker"
  stages       = [yet_cloud_environment.production.id]
  repository   = "acme/platform"
  branch       = "main"
  build_root   = "worker"
  ports        = [{ name = "http", port = 8091 }]
}

resource "yet_cloud_application" "panel" {
  namespace_id = yet_cloud_namespace.shop.id
  name         = "panel"
  stages       = [yet_cloud_environment.production.id]
  repository   = "acme/platform"
  branch       = "main"
  dockerfile   = "panel/Dockerfile"
  ports        = [{ name = "http", port = 3000, public = true }]
  env = {
    WORKER_URL = yet_cloud_application.worker.internal_url
  }
}
```

## Schema

### Required

- `name` (String) Its name.
- `namespace_id` (String) The namespace it belongs to.
- `stages` (List of String) Its environments' ids, in the order releases go through them. Each on a runtime of its own.

### Optional

- `addons_on_delete` (String) What becomes of its add-ons when it is destroyed: `keep` (the default) — they run on where they were, for the applications attached to them, until one adopts them (`yet_cloud_database_adopt`) — or `delete`, with it.
- `auto_promote` (List of String) The stages that promote to the next by themselves, once running.
- `branch` (String) The branch whose pushes are built.
- `build_on` (String) What makes a build: pushes to `branch`, or tags.
- `build_root` (String) Of a monorepo, the folder it is built from — the build's context, and where Railpack looks; the whole repository unless set.
- `cpu_millicores` (Number) What each copy may use at most, in thousandths of a core — `50` to `16000` — and what it asks for; the autoscaler measures against it. `0`, no limit.
- `dockerfile` (String) Of a monorepo, its Dockerfile, from the repository's root — `leads/Dockerfile` — so the build may reach what is beside its folder. Unless set, the folder's `Dockerfile`, or Railpack's plan.
- `env` (Map of String) Its variables, in every stage.
- `environment_size` (Attributes Map) Each environment's own size, by environment id: each field said takes the place of the application's of the same name there, by the same rules; one left out takes the application's. (see [below for nested schema](#nestedatt--environment_size))
- `liveness` (Attributes) Whether a copy is alive, restarted when not: a check on one of its ports. Left out, none: Kubernetes's own. (see [below for nested schema](#nestedatt--liveness))
- `max_replicas` (Number) Up to how many it scales to, when more than `replicas`.
- `memory_mb` (Number) Each copy's memory at most, and what it asks for, in MB — `32` to `65536`. `0`, no limit.
- `port` (Number) The default port's number: `8080` unless set. With `ports`, theirs.
- `ports` (Attributes List) Every port it listens on — `1` to `10`, names and numbers each once — replacing what it had. Left out, one `http` port on `port`, public and the default. (see [below for nested schema](#nestedatt--ports))
- `readiness` (Attributes) Whether a copy may take requests: a check on one of its ports. Left out, none: Kubernetes's own. (see [below for nested schema](#nestedatt--readiness))
- `replicas` (Number) How many run in each stage: `1` unless set.
- `repository` (String) The GitHub repository it is built from, `owner/name`, through Cloud's GitHub App.
- `scale_cpu` (Number) Where it scales out on processors, when it grows, as a percent of what its copies ask for — `10` to `95`, in steps of `5`: `70` unless set.
- `scale_memory` (Number) Where it scales out on memory, when it grows, as a percent of `memory_mb` — `10` to `95`, in steps of `5`. `0`, never on memory: the default.
- `stage_env` (Map of Map of String) Each stage's own variables, by environment id, over `env`.
- `subdomain` (String) The name it answers at under its stages' domains; its name's when left out, `@` for the domain's root.
- `tag_pattern` (String) The tags that make a build, when it builds on tags: `v*`.

### Read-Only

- `id` (String) The ID of this resource.
- `internal_url` (String) Where its default port answers inside its stage's cluster — `http://<id>.<namespace id>.svc.cluster.local`, on port 80; another port of its, on its own number — to the applications of its namespace alone.
