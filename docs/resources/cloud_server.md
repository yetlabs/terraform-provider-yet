# Resource: yet_cloud_server

A machine of a local rack, which Yet's agent runs on. Made, it waits for its machine: run `join_command` there — in a VM's user data, say — and it comes online.

-> **Note:** The join command's token works once, and for a while. It is made when the server is; a machine that joins later needs a new one, from Yet's apps or the API.

## Example Usage

```terraform
resource "yet_cloud_server" "box" {
  name    = "box"
  rack_id = yet_cloud_rack.home.id
}

# A VM that joins Cloud as it boots.
resource "aws_instance" "box" {
  ami           = "ami-0abcdef1234567890"
  instance_type = "t4g.medium"
  user_data     = "#!/bin/sh\n${yet_cloud_server.box.join_command}"
}

# An EC2 instance Cloud starts in an AWS account connected for Servers: it
# joins by itself as it boots; destroying it ends the instance.
resource "yet_cloud_server" "ec2" {
  name           = "ec2-1"
  rack_id        = yet_cloud_rack.home.id
  aws_account_id = yet_settings_aws_account.production.id
  instance_type  = "t4g.medium"
  disk_gb        = 50
}
```

## Schema

### Required

- `name` (String) Its name: lowercase letters, digits and dashes, up to 32, starting with a letter.

### Optional

- `aws_account_id` (String) An AWS account connected for Servers (`yet_settings_aws_account`'s `id`): Cloud starts an EC2 instance there, which joins by itself as it boots; destroying the server ends it. Left out, a machine of the company's, joined with `join_command`.
- `disk_gb` (Number) Its disk, 20 to 1000 GB; 30 when left out.
- `instance_type` (String) The instance's type, one Cloud offers (`t3.small`, `t4g.medium`, `m7i.large`…); `t3.small` when left out.
- `rack_id` (String) The local rack it joins; the company's only one when left out.
- `region` (String) The instance's AWS region; the account's when left out.
- `service` (String) With `aws_account_id`: `ec2` (the default), an instance; or `serverless` — no machine, the account itself, connected for Applications, online at once, for Lambda runtimes (`yet_cloud_runtime` of stack `aws:lambda`), a region each.

### Read-Only

- `arch` (String) The machine's architecture: `amd64`, `arm64`.
- `docker_command` (String, Sensitive) The same, as the `docker run` itself.
- `hostname` (String) The machine's own name, as its agent says.
- `id` (String) The ID of this resource.
- `instance_id` (String) The instance's id in EC2.
- `join_command` (String, Sensitive) What to run on a Linux machine to join it: it checks Docker, then runs the agent. Its token works once, and for a while; made when the server is.
- `origin` (String) Where it comes from: `local`, a machine of the company's, or `aws`, an instance Cloud starts — `aws` when `aws_account_id` is set.
- `os` (String) The machine's system: `linux`, `darwin`, `windows`.
- `status` (String) `pending` until its agent first comes in; `online` or `offline` after.
